읽기

이 데모가 만드는 것

급식실 앞에 줄이 얼마나 길고, 지금 서면 몇 분을 기다리는지, 오늘 급식은 무엇이고 영양 기준에 얼마나 맞는지를 학생·교사가 휴대폰으로 보는 화면입니다. 원래 설계는 급식실 카메라(라즈베리파이 + YOLO)가 사람 수를 세지만, 이 매뉴얼은 카메라 없이 나머지 전부를 홈 Pi 에서 세워 보는 절차입니다. 카메라 자리에는 mock_feed 라는 가짜 데이터 생성기를 둡니다.

왜 카메라 없이 먼저 하나 — 카메라는 프로젝트에서 가장 불확실한 부분입니다. 나머지(DB, API, 화면, 급식 정보, 외부 공개, 자동 실행)를 먼저 완성해 두면, 나중에 카메라가 안 될 때 "카메라만 의심하면 되는" 상태가 됩니다. 이 원칙은 Plant 프로젝트에서 "노드 없이 먼저 검증"으로 실증한 것과 같습니다.

전체 구조 — 이 지도가 매 단계 위에 반복됩니다

각 단계 머리에 이 지도가 다시 나오고, 그 단계에서 만드는 부품이 진하게 표시됩니다. 지금은 전부 켜져 있습니다.

읽는 요령: 왼쪽에서 오른쪽으로 데이터가 흐릅니다. 사람 수(또는 mock)가 queue.db 에 숫자로 쌓이고, FastAPI 가 그 숫자를 읽어 대시보드에 주고, cloudflared 가 그 화면을 인터넷으로 내보냅니다. 급식 정보는 별도 경로로 하루 한 번 meal.json 에 저장됩니다. 모든 것은 홈 Pi 한 대 안에서 돕니다.

준비물

  • Raspberry Pi 5, Raspberry Pi OS 64비트(Debian 13 Trixie, Python 3.13), SSH 접속 가능 — 현재 상태. 학교 Pi 도 같은 OS 로 설치한다
  • NEIS 인증키(개발계정) + 학교코드 — 발급 완료 (공주고 8140036, 교육청 N10)
  • GitHub 계정 (저장소 xparapx/Mealboard_Demo)
  • Cloudflare 계정 + 본인 소유 도메인 1개 — 9단계에서만 필요. 없어도 8단계까지는 전부 됩니다
  • 개발 PC (Windows). 코드는 PC 에서 쓰고 Pi 로는 git 으로 보냅니다. Git for Windows 설치 필수
  • Claude Code (PC) — 3단계부터 작업을 위임. 네이티브 설치(irm https://claude.ai/install.ps1 | iex), Node.js 불필요. Pro/Max 계정 필요

한 가지 약속 — Pi 위 폴더는 손으로 편집하지 않는다

이 매뉴얼에서 코드는 전부 개발 PC 의 저장소 클론에서 쓰고 커밋·push 합니다. Pi 에서는 git pull 과 서비스 재시작만 합니다. 팀원 여럿이 Pi 의 같은 폴더를 편집하면 충돌과 DB 락이 생기고, 무엇보다 "어느 파일이 진짜인가"를 잃습니다. Plant 프로젝트의 systemd 유닛이 새 Pi 로 따라오지 못했던 이유가 바로 이것(Pi 에서 직접 만들어 git 밖에 있었음)입니다.

SSH
다른 컴퓨터의 터미널을 원격으로 쓰는 통로. ssh 사용자@주소. 이 매뉴얼의 'Pi 터미널' 명령은 전부 SSH 로 들어가서 칩니다.
systemd
리눅스가 부팅될 때 프로그램을 자동으로 켜고, 죽으면 다시 살리는 관리자. 우리 서비스는 전부 이것에 등록합니다. 설정 파일 하나가 '유닛'이고 이름이 *.service, *.timer 입니다.
uv
파이썬 패키지·가상환경 관리 도구. pip 보다 빠르고, 어떤 버전을 썼는지 uv.lock 에 고정해 다른 Pi 에서 똑같이 재현합니다.

목표: 팀원 누구나 자기 계정으로 Pi 에 SSH 로 들어올 수 있고, Pi 의 시계가 한국 시각이며, 집 공유기를 건드리지 않고도 밖에서 접속되는 상태.
현재 Pi 상태(2026-08-27): 타임존 KST · Tailscale 설치됨(100.103.201.77) · Plant 유닛 disabled · mealboard 그룹 생성됨. 데모 단계에서는 메인 계정(xparapx) 하나로 진행하고 팀원 계정·SSH 키·비밀번호 로그인 차단은 추후.

1-1. 현재 상태 확인

먼저 손대기 전에 무엇이 돌고 있는지 봅니다. Plant 프로젝트가 같은 Pi 에 있으므로 특히 포트와 타임존을 봐야 합니다.

Plant 서비스가 enabled 로 나오면 재부팅 때 다시 올라옵니다. 당분간 안 쓴다면 끄고 잠급니다:

1-2. 타임존

Plant 의 촬영 타이머가 꺼져 있는 지금이 바꿀 적기입니다(켜져 있었다면 06:00 촬영이 9시간 밀립니다).

1-3. 팀 그룹과 계정

공용 계정 하나를 나눠 쓰지 않습니다. 누가 무엇을 했는지 로그에 남고, 나간 사람 키만 지울 수 있기 때문입니다. mealboard 그룹이 /opt/mealboard 폴더의 소유 그룹이 됩니다.

1-4. SSH 키 로그인

각자 PC 에서 키를 만들고 공개키를 Pi 의 자기 계정에 넣습니다. 비밀번호 로그인은 키가 전부 확인된 뒤 끕니다.

1-5. Tailscale — 밖에서 들어오는 길

집 공유기의 포트포워딩은 열지 않습니다(학교망에서 금지한 것과 같은 이유 — 인터넷 전체에 SSH 를 노출하게 됨). Tailscale 은 각자 PC 와 Pi 를 같은 사설망에 묶어 주어, 공유기 설정 없이 Pi 가 100.x.x.x 주소로 보입니다.

팀원은 각자 PC 에 Tailscale 을 설치하고 같은 계정(또는 초대받은 계정)으로 로그인하면 ssh minsu@100.x.x.x 가 됩니다.

확인

  • 팀원 PC 에서 ssh 이름@100.x.x.x 가 비밀번호 없이 열린다
  • date 가 한국 시각, groups 에 mealboard 가 있다
Tailscale
여러 기기를 하나의 사설망(VPN)으로 묶는 서비스. 무료 플랜으로 충분. 9단계의 Cloudflare Tunnel 과는 용도가 다릅니다 — Tailscale 은 팀 개발자가 Pi 에 들어가는 길, Cloudflare 는 학생 누구나 대시보드를 보는 길.

GitHub 웹에서 New repository → 이름 Mealboard_Demo, Public, README 없이(빈 상태로) 만듭니다. 그다음 PC 에서:

2-2. 네 개의 기본 파일

pyproject.toml 은 "이 프로젝트가 무엇을 쓰는가", .gitignore 는 "무엇을 절대 올리지 않는가", .env.example 은 "어떤 비밀값이 필요한가(값은 빼고)", .gitattributes 는 "파일을 어떻게 다루는가(줄바꿈)" 입니다.

네 파일 모두 VS Code 로 만드세요. 메모장은 .gitignore.txt 처럼 확장자를 붙이거나 인코딩을 바꿉니다. 점으로 시작하는 파일은 "도구에게 주는 설정"이라는 유닉스 관례이고, 점 뒤가 이름 전체입니다.

.gitattributes 는 Windows 에서만 필요한 안전장치입니다. Windows 는 줄 끝을 CRLF 로, 리눅스는 LF 로 쓰는데, CRLF 가 섞인 setup_pi.sh 는 Pi 에서 "bash 를 찾을 수 없음" 으로 죽고 systemd 유닛도 값 끝에 보이지 않는 문자가 붙어 오동작합니다. "모든 텍스트는 LF" 규칙을 첫 커밋에 넣어야 이후 파일 전부에 적용됩니다.

data/* 를 통째로 제외하고 두 파일만 예외로 두는 이유: DB 와 급식 캐시는 Pi 마다 다른 '상태'이고, 평면도와 영양 기준은 코드와 함께 다녀야 하는 '설정'이기 때문입니다.

2-3. CLAUDE.md 보강

기존 CLAUDE.md 에 아래 절을 추가합니다. Claude Code 가 세션마다 이 파일을 읽으므로, 지금 환경(카메라 없음, Plant 동거)을 여기에 적지 않으면 매번 SSH 로 vision 을 찾거나 Plant 폴더를 건드리려 할 수 있습니다.

2-4. 첫 커밋

PC 에서 처음 커밋한다면 git 에 "누구인지"를 먼저 알려줘야 합니다(없으면 커밋 자체가 거부되고, 이어서 push 가 src refspec main does not match any 로 실패합니다).

빈 저장소라 첫 push 가 main 브랜치를 만듭니다. 기대 출력은 * [new branch] main -> main.

여기서부터 Claude Code 를 씁니다. CLAUDE.md 가 저장소에 들어간 뒤가 정상 출발점입니다 — 그 전에 시키면 규칙 없이 일합니다. 저장소 루트에서 claude 를 실행하고, 먼저 "CLAUDE.md 를 읽고 금지 사항 5가지와 §0 을 요약해라, 파일은 만들지 마" 로 로드 여부를 확인한 뒤 "docs/manual.html 의 STEP 3 을 수행해라, push 는 하지 마" 처럼 단계 단위로 위임합니다. push 는 커밋 내용을 눈으로 본 뒤 직접.

pyproject.toml
파이썬 프로젝트의 설명서. uv 가 이걸 읽어 .venv 를 만들고 패키지를 넣습니다. requires-python 이 Pi 의 3.13 을 포함해야 합니다.
.env
비밀값(API 키 등)을 넣는 파일. git 에 올라가지 않으므로 Pi 마다 손으로 채웁니다. .env.example 은 그 '빈 양식'입니다.

3-1. 유닛 파일 4개 — deploy/

유닛 파일을 저장소 안에 두는 것이 이 프로젝트와 Plant 의 결정적 차이입니다. 코드와 같은 커밋 이력에 있으므로 새 Pi 에 clone 하면 따라옵니다. __USER__ 는 설치 스크립트가 실제 사용자명으로 바꿔 넣습니다.

Conflicts=mealboard-vision.service 한 줄이 "mock 과 vision 은 동시에 켜질 수 없다"를 systemd 수준에서 보장합니다. 한쪽을 켜면 다른 쪽이 자동으로 꺼집니다 — SQLite 쓰기 주체를 하나로 유지하는 규칙을 사람이 기억할 필요가 없어집니다.

NEIS 갱신은 cron 대신 timer 로 둡니다. 실패해도 journalctl -u mealboard-neis 에 남아 10단계의 진단 순서와 맞습니다. Persistent=true 는 05:40 에 Pi 가 꺼져 있었다면 켜지자마자 한 번 실행한다는 뜻입니다.

3-2. 설치 스크립트 — setup_pi.sh

꼭 봐야 할 줄 두 개:

  • 4번, uv venv --system-site-packages 가 uv sync 보다 먼저. 카메라 라이브러리 picamera2 는 pip 이 아니라 apt 로 설치되는 시스템 패키지라, 가상환경이 시스템 것을 '빌려 쓰게' 만들어야 합니다. 순서가 뒤집히면 venv 를 다시 만들면서 설치분이 날아갑니다 — Plant 에서 실제로 겪은 함정. 홈 Pi 엔 카메라가 없지만, 학교 Pi 와 환경을 똑같이 맞추기 위해 지금부터 이 순서로 합니다.
  • 6번, install -C -v. 내용이 같으면 건너뛰고 바뀐 파일만 출력합니다. 두 번째 실행부터 "무엇이 갱신됐나"가 바로 보입니다. Plant 의 유닛은 이름이 달라 건드리지 않습니다.

4-1. 원리 — Little's law

줄 서는 시스템이 안정 상태에 있으면 평균 대기 인원 = 도착률 × 평균 대기시간, 즉 W = L / λ 가 성립합니다. 우리는 L 을 "배식 구역(ROI) 안에 있는 사람 수", λ 를 "배식대 가상선을 최근 5분간 통과한 사람 수 ÷ 5" 로 잽니다.

두 가지를 알고 써야 합니다. 첫째, L 과 λ 는 같은 경계를 봐야 합니다 — ROI 의 출구변이 곧 λ 를 재는 선이어야 합니다. 둘째, 점심 시작 직후처럼 안정 상태가 아닐 때(줄은 빠르게 느는데 5분 평균 λ 는 아직 낮음)는 과대추정됩니다. 그래서 대시보드에 "배식 초반 오차 큼"을 적고, λ 가 너무 낮을 땐 숫자를 내지 않습니다.

7-2. PWA 파일 두 개

PWA 는 "홈 화면에 추가"가 되는 웹페이지입니다. manifest.json 이 이름·아이콘을, sw.js 가 오프라인 캐시를 맡습니다. sw.js 에서 /api/ 를 캐시하면 30초 폴링이 캐시된 옛 값만 돌려주는 함정이 있어, API 요청은 통과시키고 정적 파일만 캐시합니다.

아이콘은 192×192 PNG 아무 것이나 static/icons/icon-192.png 로 두면 됩니다(없어도 동작은 함).

폴링(polling)

서비스워커(sw.js)

학교급식법 시행규칙 [별표 3] 의 고등학생 남자 한 행입니다(공주고는 남고 — schoolInfo API 의 COEDU_SC_NM 으로 확인). 다른 학교로 옮기면 이 파일만 바꿉니다.

upper_factor 1.5 는 "권장량의 150% 를 넘으면 과다로 표시"하는 화면용 기준이지 법정 상한이 아닙니다. 법은 상한을 정하지 않습니다.

8-2. 왜 코사인 유사도가 아닌가

공모전 보고서는 영양성분 벡터와 기준 벡터의 코사인 유사도를 "영양 밸런스"로 썼습니다. 그런데 에너지(900)·칼슘(300)·비타민A(284) 처럼 숫자가 큰 항목이 각도를 거의 결정하고, 티아민(0.44)·철(4.7) 은 사실상 무시됩니다. 게다가 모든 영양소가 절반이어도 유사도는 1.0 입니다(크기 불변). 그래서 여기서는 영양소마다 기준 대비 비율로 먼저 바꾸고, 법정 기준의 구조를 그대로 따르는 세 지표를 냅니다:

  • 에너지 충족률 = 실제 kcal ÷ 900 — "양이 충분한가"
  • 에너지 적정비율 — 탄수화물·단백질·지방이 각각 55~65 / 7~20 / 15~30 % 안에 있는가 — "균형인가". 단백질이 기준 g 을 넘어도 이 비율 안이면 문제가 아닙니다(보고서의 "단백질 초과"는 이 관점에서 재해석됩니다)
  • MAR(Mean Adequacy Ratio) = 미량영양소 6종의 min(실제/권장, 1) 평균 — "부족한 것이 있는가". 넘치는 건 1 로 잘라 과잉이 부족을 가리지 못하게 합니다

영양소별로는 평균필요량(EAR) 미만이면 부족, EAR~권장(RNI)×1.5 면 적정, 그 위면 과다. 기준이 EAR~RNI 범위인 점을 그대로 씁니다.

8-3. 코드

parse_ntr 은 NEIS 의 NTR_INFO 문자열("탄수화물(g) : 90.6<br/>단백질(g) : 30.1 …")을 앞글자 일치로 읽습니다. NEIS 가 괄호 표기를 바꿔도 견딥니다. 주말·방학이면 API 가 INFO-200 을 주는데, 이건 오류가 아니라 "급식 없음"이므로 state: no_meal 로 구분해 저장합니다.

8-4. 실행

대시보드를 새로고침하면 급식 카드에 메뉴와 막대가 뜹니다. 화면 아래 "영양교사 산출값 기준 참고 지표" 문구는 남겨 두세요 — NEIS 수치는 원재료 기준 계산값이라 조리 손실(특히 비타민C)이 빠져 있고, 판정 표현은 학교와의 신뢰 문제로 이어질 수 있습니다.

EAR / RNI
평균필요량 / 권장섭취량. EAR 은 집단의 절반이 필요를 채우는 양, RNI 는 거의 모두가 채우는 양. 급식 기준은 '이 사이에 들어오면 충족'으로 읽습니다.
MAR
Mean Adequacy Ratio. 영양학에서 식사의 질을 재는 정립된 지표. 영양소별 충족비(NAR, 1 을 상한)의 평균.

9-1. 왜 터널인가

학교망은 밖에서 들어오는 연결을 막습니다. 터널은 Pi 가 밖으로 Cloudflare 에 연결을 열어 두고, 학생의 요청이 그 통로를 거꾸로 타고 들어오는 방식입니다. 포트포워딩도, 고정 IP 도 필요 없고, 443 아웃바운드만 되면 됩니다. Netlify 같은 호스팅으로는 대체되지 않습니다 — 서버(DB·API)가 Pi 안에 있기 때문입니다.

준비: Cloudflare 계정에 본인 도메인이 등록되어 있어야 합니다(무료 플랜). 없다면 이 단계는 건너뛰고 7-3 의 SSH 터널로 팀 내부 확인만 계속해도 됩니다.

9-2. 설치와 터널 생성 (Pi)

설치 명령은 Cloudflare 공식 문서 기준입니다. 바뀌었을 수 있으니 실패하면 문서를 우선하세요.

9-3. 설정 파일과 서비스 등록

저장소에는 값이 빠진 견본만 두고, 실제 config.yml 과 자격증명 json 은 Pi 에만 있습니다(CLAUDE.md §5 — 터널 자격증명은 커밋·채팅에 노출 금지).

9-4. QR

확인

  • 휴대폰 데이터(집 WiFi 끄고)로 https://meal.example.com 이 열리고 숫자가 갱신된다
  • 브라우저 메뉴에 "홈 화면에 추가"가 뜬다 (PWA)
  • https://meal.example.com/api/status 는 열리지만 SSH·Streamlit 등 다른 포트는 열리지 않는다 — 터널이 8100 만 내보내기 때문

학교 Pi 로 갈 때

cloudflared tunnel create 를 다시 하지 않아도 됩니다. Pi 의 ~/.cloudflared/<ID>.json 과 /etc/cloudflared/config.yml 을 안전한 방법(USB, scp)으로 옮기고 service install 만 하면 같은 주소가 학교 Pi 를 가리킵니다. 홈 Pi 쪽 cloudflared 는 그때 끕니다(같은 터널을 두 곳에서 켜면 트래픽이 갈립니다).

10-1. 데모 통과 조건

  1. Pi 재부팅 후 아무 명령 없이 curl localhost:8100/api/status 가 ok — systemd 가 전부 되살렸다는 뜻
  2. 대시보드 숫자가 30초 안에 바뀐다
  3. sudo systemctl restart mealboard-mock 직후 화면이 잠깐 "배식 시작 대기"(λ 계산 중) 를 거쳐 정상으로 돌아온다
  4. sudo systemctl stop mealboard-mock 2분 뒤 화면이 "데이터 없음" — 카메라가 죽었을 때의 모습
  5. 급식 카드에 오늘 메뉴와 영양 막대가 있다 (방학이면 "급식 정보가 없습니다")
  6. 팀원이 자기 계정으로 SSH → git pull → 재시작을 혼자 할 수 있다
  7. (9단계까지 했다면) 휴대폰 데이터로 외부 주소가 열린다

10-2. 안 될 때 보는 순서 — 위에서 아래로, 건너뛰지 않기

경험칙(Plant 실증): "대시보드에 안 나온다"는 열에 아홉이 그리는 쪽 문제입니다. ③에서 DB 에 데이터가 있으면 카메라·mock 은 용의선상에서 빼고 api 와 static 부터 봅니다. ③에서 없으면 반대입니다.

10-3. 해서는 안 되는 것 (CLAUDE.md §5 와 동일)

  • data/ 안 파일 삭제, DB 의 DELETE/DROP/UPDATE — 정리 도구는 ①빈 조건 거부 ②자동 백업 ③되돌리기 명령 출력, 세 겹 없이는 만들지 않는다
  • Pi 폴더에서 직접 파일 편집
  • ~/plant/ 접근 — Plant 프로젝트 소유
  • .env·터널 자격증명을 커밋·채팅·스크린샷에 노출
